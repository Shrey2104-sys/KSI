1. EXECUTIVE SUMMARY & SYSTEM OVERVIEW
--------------------------------------------------------------------------------
"Karmayogi Statistical Intelligence (KSI)" is an enterprise-grade institutional
competency analytics, automated assessment synthesis, and role-based training
recommender engineered for the Ministry of Statistics and Programme
Implementation (MoSPI) under Problem Statement SIH26101.

In alignment with National Programme for Civil Services Capacity Building
(NPCSCB) - "Mission Karmayogi Bharat", KSI eliminates legacy, ad-hoc administrative
training by establishing an algorithmic, data-driven bridge between an officer's
empirical competency vector and customized learning pathways on the iGOT
Karmayogi Bharat platform.

Key Deliverables Achieved:
1. End-to-end data persistence using pure SQLite (`ksi_master.db`), completely
   rejecting ephemeral in-memory mock objects.
2. Air-gapped local Large Language Model integration via Ollama (`qwen2.5:7b-instruct`)
   for confidential dossier parsing and psychometric question synthesis without
   leaking sovereign government data to public third-party APIs.
3. Dual-Stack Production Deployment:
   - Primary Modern Web Portal: Vite + React 18 + Tailwind CSS frontend adopting
     the official iGOT Karmayogi Bharat design system, backed by a high-throughput
     FastAPI asynchronous REST service.
   - Production Fallback Application: Pure Streamlit data portal preserved
     100% untouched and fully operational as an emergency offline fail-safe.

5. TECHNICAL & PROCESS CHALLENGES FACED AND APPLIED ENGINEERING FIXES
--------------------------------------------------------------------------------

CHALLENGE 1: In-Memory Mock Fallbacks vs. True SQLite Disk Persistence
----------------------------------------------------------------------
- Problem: Early prototypes often rely on in-memory dictionary mocks. Upon reloading
  the module (`importlib.reload(db)`) or restarting the dev server, all modified scores
  and enrolled courses would silently reset to hardcoded defaults, destroying data integrity.
- Engineering Fix:
  Created an idempotent SQLite initialization routine in `db.py` using `CREATE TABLE IF NOT EXISTS`
  coupled with `SELECT COUNT(*)` seed guards. Configured atomic upserts:
  `INSERT INTO officer_scores (officer_id, domain, score) VALUES (?, ?, ?) ON CONFLICT(officer_id, domain) DO UPDATE SET score=excluded.score`
  All transactions commit immediately to `ksi_master.db` on disk.

CHALLENGE 2: CPU LLM Inference Latency & The 8.0s Timeout / Retry Freeze Trap
-----------------------------------------------------------------------------
- Problem: Running a local 7-billion parameter LLM (`qwen2.5:7b-instruct`) on standard
  CPU hardware generates structured JSON tokens at approximately 10–12 tokens/second.
  Synthesizing 3 complete Bloom-tiered MCQs requires ~120–150 tokens (~9–11 seconds).
  A standard 8.0s timeout prematurely killed the inference mid-stream. Furthermore, the
  OpenAI Python SDK's default `max_retries=2` caused the client to retry twice upon timeout,
  freezing the UI for 24 seconds before finally failing, appearing as an application crash.
- Engineering Fix:
  In `engine.py`, reconfigured the client with zero automatic retries (`max_retries=0`)
  and calibrated the timeout threshold to `OLLAMA_TIMEOUT_SECONDS = 12.0`. This gives
  legitimate CPU generation adequate time to finish cleanly while instantly failing fast
  without redundant freezes if the Ollama daemon is unresponsive.

CHALLENGE 3: Domain Canonicalization vs. Shorthand Alias Querying
-----------------------------------------------------------------
- Problem: Different parts of the system refer to competency domains differently. Course
  curricula use colloquial titles (e.g., "Technical Tools"), while formal role benchmarks
  use full statutory names (e.g., "Technical Tools (Python, R, SQL, GIS)"). Direct SQL
  equality matches (`WHERE domain = ?`) caused valid courses to return empty lists.
- Engineering Fix:
  Standardized the database schema on canonical strings and created a multi-tier resolution
  engine in `get_courses_by_domain()`. The query checks exact canonical matches, dictionary-mapped
  aliases (`DOMAIN_CANONICAL_MAP`), and bidirectional substring containment (`LIKE`).

CHALLENGE 4: Dual-Access Compatibility for Zero-Latency Precomputed Demo Cache
------------------------------------------------------------------------------
- Problem: To guarantee offline presentation resilience during hackathon evaluations,
  a precomputed cache was created. However, different consumers required different types:
  some routines expected native Python dictionary lookups (`cache[key]["scores"]`),
  while other routines executed `json.loads(cache[key])` expecting a serialized string.
- Engineering Fix:
  Engineered a custom dual-nature `JsonResponse` class inheriting from `str` while
  implementing dictionary methods (`__getitem__`, `get`, `keys`, `items`, `values`).
  Both string parsers and direct dictionary indexers consume the object without errors.

CHALLENGE 5: Strict Workspace Preservation Directive
----------------------------------------------------
- Problem: The user commanded that the existing Streamlit application (`app.py`,
  `engine.py`, `db.py`, `models.py`, `requirements.txt`, and `ksi_master.db`) must remain
  100% untouched and intact as a production fallback, while building a full React +
  FastAPI enterprise web portal.
- Engineering Fix:
  Isolated all new infrastructure inside a dedicated `web_portal/` directory:
  - `web_portal/backend/api.py`: Dynamically prepends the parent root to `sys.path`,
    importing verified modules directly without duplicating or modifying existing code.
  - `web_portal/frontend/`: Standalone Vite project communicating exclusively over REST.

CHALLENGE 6: Distractor Deduplication & Case-Insensitive Normalization
----------------------------------------------------------------------
- Problem: LLM generation occasionally outputs repetitive distractors or slight case
  variations (e.g., "The Laspeyres formula", "laspeyres formula", "Laspeyres Formula").
- Engineering Fix:
  Implemented `clean_term()` in `engine.py` using regex `^(the|an|a)\s+` to strip English
  articles and normalize casing. Questions with duplicate options are caught and cleansed
  prior to serialization.

CHALLENGE 7: Windows Python Execution Alias Conflict
----------------------------------------------------
- Problem: Running `python3` in the Windows PowerShell terminal triggered the Microsoft
  Store App Execution Alias rather than the active Python 3.11.5 interpreter.
- Engineering Fix:
  Explicitly invoked the canonical `python` executable and verified module execution paths,
  preventing silent launch failures.
